## Acceptance scenarios

| Scenario | Current evidence / remaining gate |
|---|---|
| A Happy path | Browser verified with scanned synthetic fixture, real app/DB/S3/scanner and second approver; live Azure smoke remains blocked |
| B GST correction | PostgreSQL integration proves blocking GST→correction→submission |
| C Duplicate | Candidate evidence/decision version scope and duplicate-export protection tested |
| D PO mismatch | Over-consumption and exact decimal differences tested; full authorized amendment UI scenario pending |
| E Human review | Browser correction and save/revalidation/submission pass |
| F 100 documents | 100 independently accepted documents/jobs, re-upload dedupe, single-item reprocessing tested using test adapters |
| G Provider outage | Three attempts, persisted failure, safe recovery without overwriting human version tested |
| H Tenant isolation | Unauthorized organization invoice/document/supplier/PO/export requests denied; broader multi-membership adversarial suite still needed |
| I Unauthorized approval | Processor direct API call denied |
| J Concurrent edits | Stale version rejected; original/current versions retained |
| K Concurrent allocations | Two competing approvals cannot consume more than ordered quantity |
| L Export failure | Failure persisted; retry retains one batch and record, no duplicate export |
| M Usability | Browser/responsive screenshots and automated accessibility checks; exhaustive critical-screen manual review remains incomplete |
| N Provenance | Original evidence and immutable manual correction versions retained; reprocessing preserves corrections |
| O Audit | Browser timeline identifies correction, submission, approval and export; DB trigger rejects audit deletion |
